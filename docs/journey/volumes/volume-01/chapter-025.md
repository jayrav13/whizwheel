## Chapter 25 — The font bug and the frontend agent's first real iteration (2026-06-13)

This is the chapter where the verification machinery built across Chapters 22–24 *caught a real defect*, and the frontend agent did its **first real iteration** — not a greenfield dogfood, but fixing a bug it could now detect through its own screenshot self-review. It is the strongest single piece of evidence in the arc that the loop *closes*: build → see → catch → fix → re-see → prove.

**The CI/Linux render exposed what local review hid.** Reviewing PR #10's CI-generated screenshots (pulled via `bin/ci-screenshots`), the assistant compared the CI render to its local capture and caught the bug:

> "That download just paid for itself — look at the CI render versus what I saw locally. Same page, **different font** … That exposes a real bug: our `--font-sans: 'Inter', 'Helvetica Neue', system-ui` stack **never actually loads Inter** — there's no `@font-face`/web font. So Mac users get Helvetica Neue, and **everyone on Linux/Windows/Android gets a plain system sans, not the 'sharp grotesk' BLEND intends.** Local review hid that; the neutral CI environment surfaced it."

This is precisely the *"incidental CI benefit"* the assistant had named in Chapter 23 — rendering in CI's neutral Linux env as a proxy for a non-Mac visitor — earning its keep on its first real outing. The local Mac render silently fell back to Helvetica Neue, hiding the missing web font; the Linux runner showed a generic sans, and the line-wrap difference (*"'verifiable to the decimal' breaks in a new place"*) made it visible.

**A small detour the user opened, recorded honestly.** Before the fix, the assistant laid out two ways CI could *actually evaluate* pixels (rather than just archive them): a **Claude-vision CI step** posting an advisory PR comment (*"the most on-thesis option: it's literally 'judge taste with a model,' in CI"* — but recommended as advisory, not a hard gate, *"because taste is fuzzy"*), and **deterministic visual-regression diffing** (*"catches 'it changed,' not 'it's bad'"*). The user's choice was the cleaner session-side design (Chapter 23's loop), and the assistant deferred the dedicated vision subagent until calculator pages make the image-token cost worth offloading. The font fix was prioritized as *"a real defect."*

**The fix: deliver the design, don't change it.** The user said *"font fix next."* The assistant framed the fix as design-faithful: *"`DESIGN.md` already specifies Inter, so we **deliver** it (self-host via `@font-face` + Propshaft — keeping the app self-contained, no Google-CDN runtime dependency), rather than changing the design to system fonts."* It branched #11 off `main` and **dispatched the frontend agent** — its first real iteration.

**What the agent did — and the boundary it respected.** The assistant's review of the agent's work is the experiment data point of the chapter:

> "The frontend agent **self-hosted Inter**, **self-reviewed its own screenshots** (it has vision) to confirm the font loaded, added a `document.fonts.check` test to *prove* delivery, and **respected its boundary** — it flagged the `DESIGN.md` edit for me and confirmed no `config/` change rather than crossing into either."

The independent review confirmed the craft: *"the `@font-face` is correct (variable `font-weight: 400 800`, `swap`, woff2), the preload **includes `crossorigin: 'anonymous'`** (the thing that's easy to miss — it's there), and the new test asserts the font *loaded* via the Font Loading API, not just that it's named."* Three independent signals agreed the font was real — the assistant's *visual* check (*"the headline now renders in **Inter** … the hero reflowed: 'verifiable to / the decimal.'"*), the Font Loading API test, and Propshaft fingerprinting. The agent flagged the one thing it could not touch — `DESIGN.md §2` had said "no web-font fetch required," now stale — and the assistant made that docs edit itself (`d2f0908`), exactly the boundary the agent def encodes.

**Cross-platform proof — the loop's payoff.** PR #14 went green, and the assistant ran the **visual gate for real**: *"the `document.fonts.check('800 16px Inter')` assertion passed *on the Linux runner*, so Inter loads cross-platform."* Then it pulled the Linux screenshots and confirmed by eye:

> "**Visual gate passed — cross-platform proof complete.** The CI/Linux render now shows **Inter** (compare to the earlier Linux renders that fell back to a generic sans — same reflow as my local Inter capture, the fallback is gone). … The whole loop worked: CI generated → `bin/ci-screenshots` pulled → I reviewed → confirmed."

PR #14 (`Closes #11`) merged as `d515f12`, issue #11 closed.

**Where it paused.** Per the user's plan — *"once this wraps up, let's journal and pause, we'll start the backend agent in a future session. We want to verify what we have remaining for the frontend agent and get all of that pushed and merged"* — the assistant ran a frontend audit. Its verdict: the **current phase is complete and fully landed** — #7 (agent + BLEND + dogfood), #9 (screenshot verification), #12 (visual-gate tooling), #11 (font fix) all on `main`; nothing frontend uncommitted, unpushed, or unmerged. The one deferred refinement — the component extraction the agent self-flagged in Chapter 22 — was filed as **issue #15**, *"intentionally held until calculator pages exist, to avoid premature abstraction."* Calculator UI / history / admin pages are frontend-agent scope but blocked on the backend (issue #6), correctly next-phase. The session ended here, with the historian fired to completion on `main` (the end-of-session inversion from Chapter 11).

**Agent-driven?** ✅ The font fix — real product code — was written by the frontend agent, which *also* verified its own work (self-reviewed screenshots, wrote a delivery-proving test) and *respected its boundary* (flagging rather than crossing into `DESIGN.md`/`config/`). The main thread's actions were the independent review, the one in-lane docs sync, the visual gate, and git mechanics. The deferred extraction (#15) was held deliberately to *avoid premature abstraction* — a discipline choice, not an oversight. This is the first time the verification loop the experiment built actually caught a defect *and* the agent it built fixed it within its lane.
