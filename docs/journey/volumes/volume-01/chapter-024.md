## Chapter 24 — The testing canon: lifting "every feature ships tests" out of one agent and into the shared layer (2026-06-13)

A short but structurally important chapter: the user asked whether the testing practice was *canonical*, the assistant checked the actual written canon rather than its memory, found the practice living in the wrong layer, and lifted it into the doc every agent reads.

The user's question was precise: *"What approach have we codified for adding these tests? Like, do the UI tests canonically get added in for all work based on what we've codified?"* The assistant answered *"from what's actually written, not from memory"* — it grepped the docs and agent defs — and reported the uncomfortable finding plainly:

> "Good instinct to check the canon rather than trust that it's consistent — because it isn't quite. … There's exactly **one hard, mechanical gate**: 100% line+branch coverage … Everything UI-test-related is **instruction, not a gate** — and it lives in **one place**: `.claude/agents/frontend.md`."

The real finding — and it cuts against the experiment's own Chapter-5 hierarchy: *"The convention drifted into the agent def, not the shared canon. … `ARCHITECTURE.md §11` is supposed to be the *single source of truth for how we test* — the doc **every** agent reads. But §11 says nothing about system tests, screenshots, or the `NO_COVERAGE` split. The whole UI-testing approach exists only inside `frontend.md`. §11 is also now **stale**."* So per the project's own documented layering (conventions live in the docs agents read; agents *reference* them), the UI-testing approach was *"encoded in the wrong layer."*

The user named exactly what he wanted made true: *"I'd like to ensure that it's canonically true that when we work on features, tests are put into place for the backend and the frontend, and that this UI review takes place for frontend testing."* The assistant rewrote **`ARCHITECTURE.md §11`** to open with **"Every feature ships tests — no feature merges without them,"** then a per-layer table (backend → unit/reference-value + integration; frontend → integration + system + full-page screenshots + a *mandatory visual review*), documented the coverage-gate scope (Ruby unit/integration counted; ERB not) and the `NO_COVERAGE` system-pass rule, and dropped the stale snippet/CI note. It added the one-line mandate to **CLAUDE.md** (the inherited contract) and pointed **`frontend.md`** at §11 as the canon it operationalizes (DRY). As the assistant put it, this means *"when the backend agent gets built, it reads §11 and inherits this automatically (no per-agent restatement)."* The change rode into PR #10 (retitled, `e669b9a`), which went green and merged (`37b4de0`).

**Agent-driven?** ✅ entirely. The fix was *moving a convention to the correct layer* — exactly the experiment's discipline applied reflexively: a practice that had accreted in one agent def was lifted into the shared doc all agents read, so future agents inherit it without restatement. No app code touched. This is also a clean instance of the verification habit — the assistant checked the *written* canon (grep) before answering whether something was canonical, and found it wasn't.
