## Chapter 94 — The operator overrules the agent: a DB-backed registry, deliberately, against the assistant's recommendation and rule #3 (2026-06-14)

This is one of the experiment's pivotal moments — the operator overriding both the agent's architectural recommendation *and* one of the repo's own load-bearing rules, on purpose. The fork the assistant had flagged ("where does calculator metadata live?") drew the operator straight to the substrate question: *"Is this essentially requesting the need for a DB table that tracks every type of calculator? If that is one of the best foundational options, I think we should move forward in creating that registry."* He sketched the mechanism himself — a migration that migrates all calculators into the DB in one shot, plus *"a small playbook on how to idempotently re-insert (shape of the inserted data, queries executed)."*

The assistant pushed back, hard and on principle rather than just building it. Its recommendation was a **code registry, not a table**, and it grounded the objection in the repo's rules: *"A DB table that tracks every calculator type is a central registry — and rule #3 is 'no central registration — add a calculator by adding a file; never edit a shared registry/route/table.'"* It argued a seed/migration insert would become *"the new merge-conflict point — which is the precise problem #107 exists to eliminate. You'd move the collision from three ERB files to one seed file. Net zero, arguably worse,"* and that it would couple the pure math layer (rule #5: no DB) to data that is *"100% derivable from code."* It proposed instead an autoload-aware class registry — each calculator self-declaring `title`/`category`/`blurb` in its own file, with `Base.all` globbing `app/calculators/*.rb` — and showed how the operator's "migration + idempotent re-insert" instinct maps onto it *for free*: *"recomputed every boot from the source of truth, so it's idempotent by construction — zero drift, no seed to keep in sync."* It conceded a table would be justified later for analytics joins or an admin-editable catalog, but *"even then you'd sync it from Base.all, not hand-maintain it."*

The operator heard the argument and overruled it with a single load-bearing sentence: *"I get why you're pushing for a code registry, but that's just tons of hard coded data about the most important component of the entire app."* He chose the DB deliberately — *"Let's go with all of these living in a DB"* — and specified the operating model: a migration that creates the tables *and* executes a newly created rake task which idempotently ingests the data, refreshed via CLI on demand, with the **database-agent owning that capability** (*"when we ask for this, kick db agent which knows how to do the steps"*). His framing of the assistant's own pre-work: *"converting all inventory into a deterministic shape that gets ingested by the rake task, maybe the output here is a CSV."* He also bounded the blast radius — *"I don't think there's anything that we can or should update right now based on this … We still need UI's for each of these individually in code"* — and, notably, asked the assistant to *stress-test his own decision* rather than just execute it: *"do an investigation on what else should change given this data … And yes evaluate my flows in ingest. and confirm once more of course that this solution works."*

The assistant accepted the reversal cleanly and without litigating it further: *"Decision heard — DB-backed registry, database-agent owns the refresh capability. Your call, and it's a deliberate evolution of the architecture, not an accident."* **Agent/doc-driven? — a deliberate human override.** This chapter is the experiment recording its own boundary: the agent argued the architecture-purist position (and rule #3) faithfully, the human weighed it and chose the opposite for a reason the agent had not weighted as heavily — that the catalog is *the* central component and burying its data in hand-coded class methods is itself the wrong kind of "registration." The override is the point of the entry, captured verbatim and unjudged.
