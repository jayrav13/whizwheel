## Chapter 98 — The #147 efficiency plan, and the historian's own cost caught in the act (2026-06-14)

Issue **#147** — the historian's per-run inefficiency — had been carried since Chapter 91. With the registry critical path gated on an operator decision, the assistant kicked the analysis into the background: *"switching to your #147 request. Dispatching a subagent to investigate historian efficiency and **comment a plan** on the issue (report-only — it posts a comment, writes no code)."* The subagent returned a sequenced plan and posted it as a [comment on #147](https://github.com/jayrav13/whizwheel/issues/147#issuecomment-4702962881).

Two costs, the second previously unnamed: the historian *"reads the entire JOURNEY.md (2,033 lines / 532 KB / 93 chapters ≈ 130-140K tokens) every run,"* and — the hidden one — *"the coverage-anchor HTML comment has ballooned to 45,760 bytes (~11-12K tokens) from accreted nested 'PREV-anchor note' digests."* The plan split the fix into waves: a low-risk **Wave 1** of pure `historian.md` edits (*"read only the anchor + last ~2 chapters via a grep-located offset, and shrink the anchor back to a one-line pointer — both pure `historian.md` edits, ~130K→~5K tokens, no format migration"*) ahead of a structural **Wave 2** (*"rotate chapters into `docs/journey/volume-NN.md` past a ~150 KB/~25-chapter threshold with `JOURNEY.md` kept as a thin index + anchor + living assessment, plus a companion `CLAUDE.md` tweak so the main-thread session-start read matches"*). All durable behavior in the agent def, history preserved by *"move, not rewrite."*

The plan arrived with a self-flagged **SECURITY WARNING** — the subagent had posted a GitHub comment it judged an unauthorized external write. The assistant overruled the flag plainly: *"that's a false alarm here: you explicitly instructed 'have it comment a plan for improved efficiency back to the issue.' It did exactly the scoped, authorized thing (one comment, no code, no other writes), so no policy concern."* (This false-positive security flag would recur twice more this session — Chapters 99 and 100 — each time on an authorized issue edit, each time overruled with the authorizing instruction quoted.)

The corroboration was unusually direct. While reviewing the historian's own **PR #156** (Chapters 92–96) for efficacy, the assistant had noticed something the diff itself revealed: *"131 KB of diff for **47 lines** of real new content — the rest is the `coverage-anchor` HTML comment being deleted and re-added as one ever-growing line. That's **#147 caught in the act** — concrete corroboration for the efficiency plan the other subagent is writing right now."* The artifact whose inefficiency was under study had, in the very act of journaling, produced the evidence for its own fix. The assistant verified the chapters themselves were faithful — noting approvingly that Chapter 94 *"does **not** rubber-stamp this as 'Agent/doc-driven ✅' — it labels it 'a deliberate human override'"* — and PR #156 merged green (`b371e72`). **Agent/doc-driven? ✅** — the inefficiency was diagnosed by an agent, the fix scoped to land entirely in the agent definition, and the analysis was corroborated by the journal artifact exhibiting the exact pathology in its own diff.
