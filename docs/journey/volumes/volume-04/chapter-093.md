## Chapter 93 — The keystone reframed: #107 is an architecture change, not a bug (2026-06-14)

With the warm-ups clearing, the operator turned to the keystone — *"Let's talk about the keystone - what's the lift on this bug."* Before estimating, the assistant read the three shared files #107 names (the `_result.html.erb` dispatch, `calculators_helper.rb`, and the home-page cards) plus the backend's discovery machinery, then delivered a reframing that reshaped the whole effort: **#107 is filed under engineering but it is not a bug.** *"There's no defect to fix; the FE just never got the convention-based discovery the backend has. That reframes the lift: the durable deliverable is a convention + agent-definition update, not a one-off refactor — otherwise the next regen erases it (rule #1)."* This is the experiment's first rule applied as a *design constraint on the fix itself*: because the regeneration sweep erases anything living only in calculator code, the keystone's deliverable has to be pushed up into the convention/agent layer or it won't survive a single round.

The assistant then mapped the three shared files into very different sizes. The **result dispatch** is *"trivial, FE-only, low risk"* — the `is_a?` chain already just renders a slug-named partial in every branch, so it collapses to one convention-based render with a generic fallback. The **helper split** is *"the real work, FE-only but touchy"* — `calculators_helper.rb` is a ~300-line monolith every frontend build appends to (not just the `field_labels_for` case but per-calc constants and methods), coverage-gated to 100%, so the honest fix is splitting it into per-calculator helper modules with a discovery convention. The **catalog** is *"medium-high, and it crosses the agent boundary"* — it needs an autoload-aware enumeration on `Base` (today nothing *lists* calculators; `lookup(slug)` only resolves a known one) plus per-calculator display metadata that lives nowhere yet. The assistant surfaced the one genuine fork early and refused to start coding before it was settled: *"The one genuine fork in the road is where catalog/calculator metadata lives — that decision shapes both the backend PR and whether #124 comes nearly for free."* It staged the lift as three PRs (backend enumeration+metadata, frontend dispatch+catalog+helper-split, agent-def harvest) plus a regen sweep, and earned the keystone label by naming what it directly unblocks: #122 (catalog UI), #124 (info modal), #143 (stat-grid), #15 (CSS collision). **Agent/doc-driven? ✅** — the keystone was correctly re-classified from "bug" to "bring the no-central-registration convention to the client side," which made the deliverable an agent/convention change by construction rather than a refactor the next sweep would erase.
