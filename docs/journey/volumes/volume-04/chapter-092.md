## Chapter 92 — The two warm-ups land, and the non-UI visual gate is proven non-functional (2026-06-14)

The three non-UI PRs from the backlog sweep's opening move — #150 (#128 rename), #149 (#144 chart rules), and #151 (the historian's Chapter 91) — all returned CI-green, and the assistant moved each into its visual gate. Per the contract, none touches a rendered surface, so each resolves through the **non-UI baseline-diff lane**: pull a main-branch CI run's screenshots as the baseline and confirm every shot is `UNCHANGED` (sha256-equal), *proving* no pixel moved rather than asserting it from the file diff. The first diff broke that promise. Diffing PR #149 against the baseline, **30 of 41 shots reported `CHANGED`** — on a PR that touched only `.claude/agents/frontend.md` and `docs/DESIGN.md`, *"neither file is rendered by the app, so no pixel can have moved."*

The contract is explicit that a surprise `CHANGED` on a non-UI PR must not be hand-waved — *"stop and view it before merge."* The assistant honored that instruction's *intent* while recognizing its likely cause, and instead of eyeballing 30 shots it ran a controlled experiment to determine whether the churn was real or capture noise: *"let me prove it's capture noise rather than assert it: diff two different main CI runs (identical code) against each other. If main-vs-main shows comparable churn, the #149 diff is noise, not the PR."* The result was decisive. Two *different* `main` CI runs — byte-for-byte identical application code — differed on **32 of 41 shots**, *more* churn than the PR's 30. The assistant's read: *"Confirmed: it's #87, not the PR. Two different main CI runs — identical app code — differ on 32 of 41 shots. That's more churn than PR #149's 30. The CHANGED reports are pure screenshot-capture non-determinism; the sha256 baseline-diff can't tell a real change from capture noise, so the non-UI 'prove every shot UNCHANGED' gate is currently non-functional (exactly what #87 describes, and why #61 wants a defined baseline source)."*

This is a notable evidence chapter: a gate that the contract *mandates on every non-UI PR* is shown, with a clean controlled measurement, to be incapable of distinguishing a real pixel change from capture noise — *"Eyeballing the 30 would be theater — main-vs-main already proves they're byte-different-but-visually-identical noise."* What actually cleared the three PRs was the file-level evidence the assistant fell back on: a table showing each PR's changed files against the question *"Rendered surface?"* — all three answered "none" (zero `app/views`, `app/helpers`, `app/assets`, `app/javascript`, layout, or calculator-math changes), so no pixel *could* have moved and the false positives were confirmed noise. The operator's instruction was terse and three-part — *"merge all 3 + document 87 evidence then move on to 107"* — and the assistant executed it: merged #150, #149, #151 sequentially (no file overlap between them) via `bin/merge-cleanup`, posted the `9 unchanged / 32 changed` main-vs-main numbers as an evidence comment on **#87**, and confirmed `main` fast-forwarded to `f405f63` with #128 and #144 auto-closed and all worktrees pruned. **Agent/doc-driven? ✅** — the warm-ups landed exactly as filed (a clean rename with history preserved, two harvested chart lessons codified into the frontend agent), and the side-effect was a concrete, reproducible data point feeding the #87/#61 fix: the non-UI gate's "prove UNCHANGED" mechanism is, today, defeated by screenshot non-determinism.
