## Chapter 84 — The iteration delivery lifecycle is codified: open → build → evaluate → harvest → journal → close (2026-06-14)

The operator named the gap directly. Reflecting on how iteration-0004 had actually unfolded, he observed that the last iteration *"should actually expand until here, because I don't think it covers updates to agents based on the results itself, which happened rather late in the game"* — the harvest had happened *after* the iteration was nominally closed, ad hoc. He sketched the corrected order — *"THEN we start a new iteration, and we *only* do regen for this one … then, we fan out agents to go regen the UI's of all of these"* — and explicitly framed it as a process-design act: *"what I'm doing here is potentially codifying an ambiguous part of our process for delivering each iteration."*

The assistant treated it as exactly that, declining to rush into agent dispatch and instead invoking the brainstorming skill: *"This is a process-design moment — you're defining the iteration *delivery lifecycle* itself, not just the next batch of work."* It diagnosed precisely what CLAUDE.md *did* and *didn't* already say — it defined iterations, the regeneration sweep, and an end-of-session checklist, but *"What it does **not** define is the per-iteration *delivery lifecycle* — specifically the **evaluate → harvest agent/process changes → propagate** phase, which is exactly what happened ad-hoc and late in 0004."*

Through the dialogue the core structural choice settled: *"the regen sweep is the propagation mechanism, and it runs every iteration"* — the next iteration regenerates the priors (carrying the prior harvest) and builds whatever new calculators are asked for, **with the new-build set allowed to be empty (a regen-only iteration).** The assistant proposed a six-phase lifecycle for section-by-section reaction — **Open → Build (fan out) → Evaluate → Harvest → Journal → Close** — with the key fix stated plainly: *"phases 3–4, *evaluate → harvest*, are named, owned, and placed **before close** — that's the ambiguity that bit us in 0004."* Two specifics were folded in and confirmed: **layer-scoped regen** (a sweep rebuilds only the layer(s) whose agents/conventions changed — frontend-only, backend-only, or both), and an amendment to the *closed* iteration-0004 log to add the harvest section that had happened after its close. The operator approved both — *"yes both correct, approved"* — and again later in full — *"yep, let's update 140 ... go all the way to PR."*

A deliberate divergence from the brainstorming skill was named: rather than write a separate spec doc, the lifecycle would be codified *directly into CLAUDE.md* — *"codifying a process *as* a doc-about-a-doc would just create drift."* It landed as PR #130 (`124cde7`, +16/−1: a new "Iteration delivery lifecycle" section plus a light touch on Rule 1 to say a sweep *"may be layer-scoped or even regen-only"*), merged at `e878c66` — and the assistant noted the recursion of practicing it as it codified it: it held the iteration-0005 fan-out until 0005 was formally *opened*, *"practicing the lifecycle we're codifying — open before build."* **Agent/doc-driven? ✅** — the operator caught an ambiguous, repeatedly-tripped-over part of the process and turned it into a named, ordered, six-phase contract in the file every agent inherits.
