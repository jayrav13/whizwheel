## Chapter 81 — The operator reviews all 8 calculators with his own eyes, and every note routes to the agent (2026-06-14)

With iteration-0004 fully closed and the app running on `:3000`, the operator did the *evaluate* phase by hand — clicking through every calculator and annotating screenshots one by one. The notes were a mix of approvals and three pointed design questions, and the framing was unambiguous: *"let's step through these notes - all changes go to the agent."* That single clause is the experiment's thesis in the operator's own words, applied to a review: nothing he found would be patched in a calculator's code; every finding would become an agent/doc change that the next regeneration sweep propagates.

The approvals were specific and grounded in real use — *"Amortization looks good, I used numbers from my actual mortgage and like what I see"*; *"Simple interest looks good"*; *"tip calculator is perfect"*; *"table at the bottom of Amortization looks good."* He also spot-checked correctness himself, asking *"is that median confirmed accurate?"* — and the assistant verified it by hand against the data: for `1, 2, 3, 4, 5, 5`, the median is the average of the 3rd and 4th sorted values, `(3 + 4) / 2 = 3.5`, with mean, mode, and range all confirmed too. The math layer held under direct inspection.

The three open notes each became an agent-bound decision, and the assistant gave its opinion before the operator confirmed (per the operator's *"Give me your opinion here, once I confirm, let's codify it in the FE agent for the next round"*):

- **Age date default (#3).** The operator asked whether date fields should default to today. The assistant argued *against* silent auto-prefill and *for* an explicit **"Today" quick-fill button** — *"Auto-filling a field silently submits a value the user never typed … A visible 'Today' chip is explicit and discoverable."* Rule for the agent: optional as-of/end dates get a Today button; primary inputs (birth date) never auto-default.
- **"Total Hours" cutoff (#4).** The operator flagged a clipped value and said it was *"unclear how to advise FE agent."* The assistant root-caused it: a rigid 4-up stat grid that couldn't fit a 6-digit value, and prescribed **auto-fit/wrap stat grids** plus *"a test with a worst-case large number so values can't clip — more durable than just shrinking the font."*
- **Amortization charting (#6).** The operator proposed a *"Major change in approach"* — swapping the CSS charts for an interactive library: *"let's ask the FE agent to use another charting library - maybe tradingview to leverage all of its hover features?"* The assistant endorsed **TradingView lightweight-charts** (MIT, ~45KB, importmap-loadable, no build step) for the time-series, then immediately flagged an honest limit: *"TradingView's **lightweight-charts has no pie/donut type**,"* so the donut needs a complementary hover-capable library. It codified the *intent* — JS hover-capable charts for all chart types, the **agent installs what's needed via importmap itself** — and left the final library choice to the agent, *"as you said, it should figure out install + fit."*

The operator also asked to file the home-grid crowding observation (*"this'll start to get crowded, file issue"*), which became **#122**. **Agent/doc-driven? ✅** — a full hands-on product review whose entire output was routed into agent definitions and issues, never into code.
