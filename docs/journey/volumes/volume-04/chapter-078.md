## Chapter 78 — "Which of the newly filed issues are quick wins?" — the post-iteration triage (2026-06-14)

With the iteration closed and the app live, the operator opened a new, distinctly *post-mortem* phase with a single question: *"Which of the newly filed issues are quick wins that can be dispatched via agents."* This is a different mode from the build itself — not making calculators, but **draining the findings queue the build had generated**, and doing it agent-first.

The assistant triaged all 13 findings against one dividing line, stated plainly: *"whether it needs a **human/design decision** or is a **substantial refactor** — those aren't quick wins."* It sorted them into three tiers. **Five true quick wins, dispatch now:** #113 (`bin/serve-headless`), #86 (`bin/merge-cleanup`), #98 (worktree-isolation hardening in the agent defs), #108 (a home-card guard test), and the eyebrow-color *half* of #112. **One bounded-but-needs-verification:** #111 (the SimpleCov parallel-merge undercount — dispatchable, but *"the agent must prove local coverage now reads 100% before claiming success"*). And **five not-quick-wins**, each with a stated reason: #107 (the frontend central-registration refactor — *"the big one … Real engineering,"* and it would *subsume* #108's whole class), #109/#110 (integer & non-numeric coercion — *"need a convention decision (truncate vs reject) + a Base-level validator"*), the financial-color half of #112 (*"a DESIGN/design call, yours to make"*), #93 (the `visual-qa-agent` — *"agent design, not trivial"*), and #87 (deterministic screenshot capture — *"medium; needs careful verification"*).

The assistant attached one self-aware caveat to #98: because no agent *owns* agent definitions yet (that is precisely the deferred meta-agent #72), the worktree-isolation hardening would go to a general-purpose agent, and — the load-bearing timing point — *"since agent-def edits change the pinned set, this is best landed **now, between iterations**, so the next regen sweep inherits the fix."* The recommendation was explicit: fire the five quick wins, *"each in its own worktree → PR → you merge."* The operator confirmed the fan-out and set the stopping rule: *"Yeah, fan all 5 out, stop short of merging - advise when all 5 are complete and have passing CI."* **Agent/doc-driven? ✅** — the very output of the build (its findings) became the input to a new agent-dispatched work phase, triaged by the same agent-vs-human-decision criterion the experiment uses everywhere.
