## Chapter 95 — The investigation that validated the operator's flow — and caught a CI-fatal bug in it (2026-06-14)

Asked to confirm his solution works, the assistant did the investigation grounded in the actual repo and returned a verdict that was neither rubber-stamp nor reversal: *"your flow works, with two corrections that are non-negotiable for CI."* The headline correction was a real bug in the operator's flow as drawn — and it turned on a detail of the repo's own configuration. The repo uses `schema_format = :sql` (`db/structure.sql`), and CI builds the test DB with `bin/rails db:test:prepare`, which *"loads structure.sql directly and runs neither migrations nor seeds."* So the operator's "migration executes the rake task" step would be **skipped in every test run**: *"A migration that runs the ingest → skipped in test/CI … The table would exist but be empty in every test run → any test reading the registry fails, and the 100% coverage gate can't pass."* The fix: the **migration creates the table only** (that's what lands in `structure.sql`); the **ingest is a standalone idempotent rake task** — *"exactly as you want for CLI refresh — just not invoked from the migration."* The assistant laid out the four-substrate resolution: fresh dev/prod DBs auto-populate via a `db/seeds.rb` hook (the existing `RoleType` pattern), CLI refresh via `bin/rails calculators:ingest`, and **tests get `test/fixtures/calculators.yml`** because `db:test:prepare` skips seeds too.

The investigation then answered the source-of-truth question the operator had left open as a CSV idea. The assistant flagged that *"a single committed CSV is a shared-edit file"* — the very conflict #107 exists to kill, relocated from three ERB files to one CSV — and offered the alternative it leaned toward: **(B) the ingest reads `docs/INVENTORY.md` directly**, because the PM already maintains that catalog idempotently and new calculator builds never touch it, so *"the registry source stays conflict-free, and there's no second place to keep in sync"* — at the cost of a missing blurb column and more brittle markdown parsing. It also named a correctness property unique to the DB substrate that the code registry never had: **the DB can drift from reality.** A row can claim a calculator the code doesn't have (a 404 link) or miss one that exists (invisible). So the ingest must **reconcile against the code** — *"The code (Base.lookup(slug)) is authoritative for 'is this actually built/routable'"* — validating each slug resolves to a class and, per rule #4's spirit, flagging vanished rows **deprecated, not deleted.**

Finally the boundary cost. The assistant surfaced that the operator's "db-agent owns this" collides with the agent's current definition: *"database-agent is hard read-only — its def says 'Read-only, full stop… never INSERT/UPDATE/DELETE… never a migration… never app code,' and it only has Bash+Read tools (no Write). It literally cannot author the CSV/migration/rake task, and running the ingest is a mutation it's currently forbidden from."* The clean split: **backend builds** the machinery (migration, `Calculator` model, the ingest **lib service** + thin rake task so the logic is unit-testable to 100%, fixtures — all its existing turf), and **database-agent operates** it (runs the ingest on request, reports before/after counts + drift), which requires *editing its definition to carve out one sanctioned mutation while keeping "no ad-hoc writes."* The assistant also enumerated the wider ripple — **CLAUDE.md rule #3 has to be amended** (*"We're deliberately creating one. The contract has to be amended to describe the new model honestly, or it contradicts itself"*), `calculations.calculator` becomes a future soft join (no hard FK — append-only calcs outlive deprecated calculators), and **routing needs no change** (already dynamic; a registry guard would make the DB authoritative over routability, bad given drift). The two calls it sent back: registry source A vs B, and whether to redefine db-agent. **Agent/doc-driven? ✅** — the agent stress-tested the human's directive and found a genuine CI-fatal defect (migration-driven ingest skipped by `structure.sql` loading) plus the drift-reconciliation requirement, validating the decision while materially correcting *how* it gets built — the override and the audit together producing a design neither party held at the start.
