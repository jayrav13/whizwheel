## Chapter 47 — Bootstrapping the page-serving seam: the one-time backend cost before every FE-only calculator (2026-06-13)

Moving to the frontend immediately hit the seam `ARCHITECTURE.md` had *deliberately deferred to "when the first calculator is built"* — and the experiment was there. The assistant named the honest structural fact: **the first calculator page couples backend + frontend** — a visitable page needs a `GET` route + a controller `show` action (backend) *and* the views (frontend), and the 100% coverage gate means the controller's render branches must be tested against real views. But it framed this as a **one-time cost**: once the generic `:slug`-based page-serving route+controller exist, *every subsequent calculator is FE-only* — same no-central-registration property as the math side.

One real decision set the pattern for all 191 pages: how the form submits/renders. The assistant proposed **Turbo Streams** (fits the Hotwire stack), and confirmed a clean property when asked — **persistence is fully preserved and format-agnostic**: `CalculatorsController#create` `record.save`s the `Calculation` *before* it renders, so a Turbo submit persists exactly like the JSON path (and later, when `record.save` becomes a background job, that's unchanged too). *"Turbo just changes the *response*, not the side effect."*

The user chose the clean division: *"send the backend agent to do the backend components of this (route controller) + new issue + PR, then send FE to do the page itself."* So the assistant created infra issue **#33** and dispatched the **backend agent** (not the main thread this time — the route/controller is squarely backend's lane).

The backend agent returned **PR #34** (`Closes #33`, 100% coverage, clean) and solved a real wrinkle cleanly. The task had suggested `render_views off`, but in this Rails 8 setup an explicit `render` still resolves a template, so a missing ERB raised `MissingTemplate`. Rather than reach into `app/views/` (the frontend's domain), it covered the render branches with **functional controller tests that prepend a test-only view path** (`test/support/views/calculators/`) holding minimal stub templates — *"these live under `test/`, not `app/views/`, so the frontend's domain is untouched — yet the action runs end-to-end."* The boundary held under pressure.

Two consequences the assistant surfaced for the user's awareness: (1) **an intentional contract narrowing** — with `respond_to`, a bare `POST` with no `Accept`/format now returns **406** (only `turbo_stream` + `json` are answered); Turbo and JSON clients both send a matching format, so it's correct, but a token-less `curl` without an Accept header will now 406; the existing JSON tests were updated to send `as: :json`; (2) **expected interim** — `/calculators/percentage` will 500 in-browser until the FE views land in #31, by design. CI green (5 jobs), visual gate 4/4 UNCHANGED.
