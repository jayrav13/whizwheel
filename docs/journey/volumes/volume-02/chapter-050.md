## Chapter 50 — The centerpiece: "the Mode pills are bunched too tightly," and learning to fix the agent, not the page (2026-06-13)

This is the chapter the assistant flagged in-session as *"a centerpiece moment for the saga"* and the user called *"a phenomenal example of the direction we're going in."* It is the experiment's first full, honest run of its own core loop — and the first time that loop *visibly failed and had to be re-aimed*.

**The flag.** Clearing #35 through the visual gate, the assistant viewed all 6 changed/new shots and gave a genuine PASS-with-notes verdict (BLEND nailed: cream bg, green-as-accent, coral-as-action, tabular hero numbers, every state correct). The user added one note: *"my only note is that the Mode pills are bnched too tightly togheter."* The assistant confirmed it by eye (*"Both the horizontal *and* row gaps are cramped"*) and named the agent-first call: this is *"the first real FE feedback,"* and the fix *"shouldn't be a one-off CSS tweak (the regeneration sweep would erase it)"* — the pill gap is really a **`DESIGN.md` gap** (no pill/tab-group spacing guidance existed), so *"the durable fix is: add that spacing guidance to `DESIGN.md`, then have the FE agent re-apply it."* The user chose **"fix then merge."**

**The principle, named by the user.** While the FE agent worked, the user articulated the thesis cleanly:

> "I think this is a phenomenal example of the direction we're going in with this journey. We're updating the agent's reference docs to give it direction, not just jumping into code"

The assistant sharpened *where the diagnosis landed*: *"We didn't say 'the FE agent rendered cramped pills' (a bug in the output); we said '**DESIGN.md was silent on pill-group spacing**' (a gap in the agent's reference material). That reframe is the whole game."* It named three things that make it more than an anecdote: the regeneration sweep makes the doc-update *mandatory* (a hand-tweak would be erased), it *compounds* (one `gap` line applies to all 191 future pages), and it's *falsifiable* — *"the testable claim is: with the guidance in DESIGN.md, the next regeneration sweep should produce roomier pills with no re-prompting."* And it named the real skill honestly: not "update a doc" but *"routing the fix to the right layer — DESIGN.md (look) vs. `frontend.md` (how the agent works) vs. the spec (what to build) — and resisting the pull to over-specify."*

**The first attempt was too timid.** The assistant's `DESIGN.md` edit set a `gap-2.5` *minimum*; the FE agent dutifully applied exactly that (`gap-2` → `gap-2.5`, i.e. 8px → 10px) and its self-review reported the pills now *"breathe."* The error-label fix (raw `v1` → "Value (V1) can't be blank", via a new `calculator_error_messages` helper) came out clean. But on re-review the assistant was honest: the pill change was *"only +2px … I wouldn't call them *roomy*."*

**The user pushed, and exposed the deeper failure.** Asked to A/B the before/after CI screenshots, the user was blunt: *"I don't see a meaningful difference … I don't think these two runs actually changed much after editing the fe agent?"* The assistant gave a straight answer: the change *did* take effect, but *"`gap-2` → `gap-2.5` is +2px, which is essentially imperceptible. My DESIGN.md guidance set the *minimum* at basically the original value, the agent applied that minimum … That's on the guidance being too timid, not a broken pipeline."* It then started to **dial the gap in live** to find the right number — and the user stopped it cold:

> "No! Don't dial it live, revert. Let's really hone in on the agent"

The assistant reverted (*"dialing it live is me doing the agent's job"*) and produced the chapter's sharpest diagnosis — the number was a *symptom*; the real failure was that **the FE agent's screenshot self-review looked at cramped pills and reported "pills breathe"** — its visual *bar* for spacing was miscalibrated. *"If we keep handing it pixel values, we're permanently doing its job — the agent will never develop the eye."* It identified **two durable agent-level levers**: (1) `DESIGN.md` has no real spacing *system* (just the word "generous" + the timid floor it had just added — *"my recent 'gap-2.5 min' made it worse by handing the agent a *floor*, which it dutifully sat on"*); (2) `frontend.md`'s self-review *"has no teeth"* (it let the agent rubber-stamp; it needs an anti-pattern checklist + a bias to err toward more space).

**The methodology pivot — use the iteration loop, not a hotfix.** The user named the larger move:

> "let's actually do this - just the spacing system. Let's do this more systematically. Let's work with the agent to solidify what we have now and then actually use iterations to iterate towards a good idea"

The assistant reflected the shift back precisely — it had been *"about to reactively patch DESIGN.md and re-dispatch the FE agent"*; the disciplined version is to **solidify the current build as the baseline, make the agent-level change, then regenerate Percentage from spec under iteration 0002 and measure whether the improved guidance *alone* produces better spacing — no hand-holding.** This **reverses the earlier "fix-then-merge"** into **"merge the imperfect baseline now, improve via the loop"** — the assistant surfaced the reversal explicitly and confirmed it twice with the user before merging an intentionally-imperfect page (*"is that the intent, or did you still want the spacing sorted before #35 lands?"*). The user confirmed: *"merge the PR as is and close out the iteration … and then start working on the design.md changes to carry forward for pills for iteration 2."*

**What landed.** **#35 merged as-is** (`1408d0a` via PR) — Percentage page on `main` as the **iteration-0001 baseline**, #31 closed, cleanup done. The PM was dispatched to **log + close iteration 0001** in its own docs PR (**#37**), capturing the build outcome *and* the key data — the cramped pills **and the self-review declaring them "roomy."** Then the assistant drafted the **`DESIGN.md` spacing scale** for the user's review: a **relationship-based rhythm** (closer = more related), six named tiers (Affix `gap-2` / Grouped `gap-3` / **Grouped-wrapping `gap-x-3 gap-y-4`** / Stacked `space-y-5` / Section `mt-7–8` / Layout `gap-8`), framed as **targets, not minimums** (*"when in doubt, go one step more open"* — directly killing the failure where the agent sat on a floor), with two rules: wrapping groups get a larger row-gap than column-gap, and tappable chips/pills *"never keypad-dense."* The user approved (*"This all looks good"*); it landed as **PR #38** (`08b83ef`), the iteration-0002 agent change.

**Agent-driven? ✅ (and the cleanest example yet).** Every correction was routed *up* into the durable layer: the spacing fix into `DESIGN.md` (not the page), the self-review weakness named as a future `frontend.md` change. The user twice stopped the assistant from doing the agent's job — once forbidding live pixel-dialing, once redirecting a hotfix into the iteration loop. The deepest data point: the experiment's *own loop failed visibly here* (a too-timid doc edit + an agent self-review that rubber-stamped cramped output), and the response was not to abandon the loop but to **re-aim it** — make the doc a *system* not a floor, and set up a clean measurement of whether that alone is enough.
