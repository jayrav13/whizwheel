## Chapter 106 — Two PRs not three, the code-only-fix caveat named, and a new iteration "let it rip" (2026-06-14)

With the Now+Low bug bucket triaged (Chapter 105), the operator moved to dispatch the fixes — and then, in the same breath, opened a new iteration. This chapter captures two decisions that both turn on the experiment's core rule (*fix the agent, not the code*): the deliberate flagging of a fix that *cannot yet* be made durable, and the kickoff of a fresh round of calculator builds with the PM run blind.

**"Can all 3 (109-111) be sent as subagents in a worktree to open PR's?"** The operator's question presumed three dispatches; the assistant corrected the count up front: *"Yes — with one structural tweak: it's **2 PRs, not 3**, because #109 and #110 share the same fix surface (`Calculators::Base`) and the github-agent recommended bundling them."* The plan: **Dispatch A** → backend agent, worktree `fix/109-numeric-coercion` → PR closing #109 + #110; **Dispatch B** → backend agent, worktree `fix/111-simplecov-undercount` → PR closing #111. They were confirmed to *"touch disjoint files (Base validation vs. SimpleCov config), so they run safely in parallel"* — the same disjoint-files reasoning that has gated every parallel fan-out in this repo.

**The code-only-fix caveat — named, not buried.** This is the chapter's load-bearing moment for the experiment's thesis. The assistant flagged, *up front and as a deliberate choice*, that the durable half of #109/#110 cannot be delivered by the backend agent:

> *"the *durable* half of #109/#110 is 'codify the convention in the backend agent definition' — but the backend agent **cannot write agent definitions** (and the meta-agent for that, #72, isn't built). So these subagents will fix the **code + tests** (which propagates to all calculators via `Base`), but per rule #1 a fix living only in code gets erased by the next regen sweep. I'll handle the `.claude/agents/backend.md` codification myself after the PRs land, so the convention is durable. Flagging so it's a deliberate choice, not a silent gap."*

This is exactly the failure mode CLAUDE.md rule #1 is designed to catch — a fix that lives only in calculator code is erased by the regeneration sweep — and here it is anticipated *before* the work runs, not discovered after a sweep wipes it. The structural cause is the still-unbuilt meta-agent (#72): no registered agent owns agent definitions, so the durable codification falls to the main thread / human. The assistant committed to doing that codification on `.claude/agents/backend.md` once the PRs land. The two backend agents were fired in the background, each in its own worktree, with the assistant noting it would *"dispatch the `quality-assurance-agent` to run the pre-merge gate"* as each PR opens — the QA gate's first real exercise being deferred to whenever those PRs surface.

With that said, I think it's time for another iteration! Let it rip? Let's see what the next 5 calculators are that the PM recommends we work on."* Two things land here. First, the bug PRs are explicitly parked for the **harvest** phase of the lifecycle (Open → Build → Evaluate → Harvest → Journal → Close) — fitting, since the #109/#110 fix is precisely an agent-definition change that the harvest phase exists to absorb.
