## Chapter 109 — The shared stat-grid: the visual gate fails twice, the `--wide` modifier, and the fix landing as a code+agent+doc set (2026-06-14)

The other half of the harvest was #143 — collapsing six divergent inline stat-grid widths into one shared component. Where the numeric guard (Chapter 108) tested the *code-review* layer, #143 tested the *visual gate*: it FAILed QA twice, each failure a real fidelity regression that only an eyes-on review could catch, and each fix tightening the design-system convention. This chapter also lands the harvest's smaller PRs and the session's process meta-work.

**First, the clean merges.** Before #143 played out, the two simplest harvest PRs landed. **PR #172** (the #111 SimpleCov undercount fix) came back QA PASS — *"CI green across all 5 jobs, visual diff pure #87 capture noise"* — and the operator asked for a once-over before merging it and the journey PR (#173). The orchestrator reviewed the actual diffs itself (PR content being fair game), confirming #172 was *"correct and well-contained (only `test/test_helper.rb`)"* — each fork gets a unique `command_name` + `use_merging true`, flushes in `parallelize_teardown`, and the main process collates in `Minitest.after_run` so the 100% gate is enforced *once against the merged total* (the per-process minimums correctly set to 0, with a `merge_timeout 3600` guard). Both merged, `main` at `319dba8`. **PR #173 was the QA gate's first live trial as the contract gate** — the bootstrap named back in Chapters 104–105 — and it worked: CI green, the non-UI baseline-diff lane adjudicated 22 CHANGED shots as #87 capture noise by eye (correctly *not* auto-failing), and it self-recovered from a transient `bin/ci-watch` NO-RUN blip rather than mis-reporting.

**PR #176 — the shared component — FAILed QA the first time, on a real regression.** The frontend agent delivered `.stat-grid`/`.stat-card` (with `--solved`/`--surface` modifiers), migrated 7 result views, deleted every inline auto-fit track, 100% coverage. The toolkit `code-reviewer` had flagged it *clean* but pointed at one spot for the visual gate to check (Ohm's Law packing more cards). QA found the regression there: it standardized all six pages onto a single 9.5rem track, but **Ohm's Law (was 13rem)** and **Simple Interest (was 11rem)** had used *wider* tracks deliberately to keep large values on one line. The QA verdict, verbatim on the worst case: *"on `24-ohms-law-large-values` the standardized 9.5rem min collapses the old 2×2 (13rem) grid to 3+1, forcing big values to **wrap mid-number**: Power '998,001,000 W' (single line on `main`) now renders as '998,00 / 1,000' — genuinely hard to read as one figure, and could be misread as two values."* Simple Interest had a milder version (`$1,000,000.00` wrapping at the cents). The QA agent was careful to distinguish this from #87 noise — *"Input columns are pixel-identical between `main` and PR, so this is **not** #87 noise"* — and named the core tension: one canonical width vs. large-value fidelity.

**The fix held the consolidation: a sanctioned `--wide` modifier, not six ad-hoc widths.** The orchestrator framed the decision: *"The resolution is still consolidation — a *sanctioned* variant rather than 6 ad-hoc widths."* The rework added `.stat-grid--wide` at **13rem**, measured in-browser (*"At 9.5rem: 3 cards per row → 155px cards → values wrap to two lines ... At 13rem: 2 cards per row → 239px cards → every worst-case value+unit sits on one line"*), applied only to Ohm's Law + Simple Interest. The frontend agent also added a reusable `assert_no_mid_value_wrap(css)` system-test helper that measures laid-out value geometry (a wrapped figure is ~2× line-height) — and verified it is not a no-op: *"forcing the modifier to 9.5rem produces height 72px and the assertion fails; at 13rem it's 36px and passes."* A geometry regression now has a real test guarding it.

**The companion durable halves — frontend agent def + DESIGN.md.** Mirroring the #175 pattern, the orchestrator codified the `--wide` convention into the **frontend agent definition** (PR #178) — the frontend agent had flagged this itself as outside its write boundary — and dispatched the PM to document the component in **DESIGN.md §4** (PR #179), replacing the old "implement a responsive auto-fit grid" guidance (the very wording that produced six divergent widths) with the canonical component + its bounded modifier set. The orchestrator named the emergent pattern: *"the durable-convention pattern means each fix now lands as a *set* (code + agent-def + docs), so a regen reproduces it."* Both #178 and #179 came back QA PASS.

**Then #176 FAILed QA a *second* time — a new clipping regression.** The `--wide` fix resolved Ohm's Law and Simple Interest, but the consolidation surfaced a fresh problem the orchestrator relayed: *"the consolidation surfaced a *new* clipping regression: MMR's 7-digit Mean/Median/Range values clip because `.stat-card`'s `overflow-hidden` meets the default 9.5rem track with no break handling — a DESIGN §4 'never clip' violation."* A second rework went in flight (MMR `--wide` + a never-clip safety net). Crucially, the orchestrator flagged a *coupling* this created: MMR's large values are unit-*less* 7-digit numbers, so if the rework broadens the `--wide` criteria to include large unit-less values, then #178 and #179 — which currently word the criteria as "unit-bearing or 7+ digit money" — *"will each need a one-line wording update and a quick re-gate ... so the code, agent def, and design doc all agree before you merge the #143 set."* The harvest holds the #143 trio (#176/#178/#179) *together* precisely so the three layers don't drift out of agreement — the lockstep discipline from #174/#175 applied again.

**The throughline named.** As each fix landed, the orchestrator repeatedly named what the session was demonstrating: *"This is the experiment working as designed — the toolkit + QA caught two real regressions (a silent Base-invariant hole and a large-value wrap) that CI alone would've shipped"* and *"this batch validated the whole loop — toolkit review caught a silent Base-invariant hole (#174 writer-bypass), the QA visual gate caught a real large-value wrap regression (#176), and both fixes drove convention changes up into the agent definitions where rule #1 keeps them."* The review loop (QA gate + toolkit reviews + the manual intent-vs-result pass) caught defects that no single layer would have, and every fix propagated up into the durable agent/doc layer.
