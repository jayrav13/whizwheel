## Chapter 103 — The keystone #107 delivered and merged: the operator views the registry-driven catalog live and says "this is great" (2026-06-14)

This is the chapter where the keystone — `#107`, the architecture change the operator chose in Chapter 94 and the registry made possible in Chapter 101 — became live, merged product, reviewed by the operator with his own eyes against a server the main thread stood up from the in-flight worktree.

**The build (PR #168, `Closes #107`).** The frontend agent delivered the three pieces Chapter 93 had sized, all in the frontend lane reading the registry. (1) A **result-dispatch convention**: `_result.html.erb` now renders `calculators/results/<slug>` via a new `calculator_result_partial(calc)` helper that resolves the per-slug partial with `lookup_context.exists?` and falls back to a generic partial — *"The `is_a?` chain is gone; the `nil` empty state and `errors.any?` validation state are byte-for-byte unchanged."* (2) A **per-calculator helper split**: the *"~300-line `CalculatorsHelper` monolith"* split into eight per-calculator modules `Calculators::<Slug>Helper`, one file each, with `field_labels_for` resolving the module dynamically by slug (`"Calculators::#{slug.camelize}Helper".safe_constantize`) *"replacing the hand-edited `case`"*; shared formatters stay in `CalculatorsHelper`. (3) A **registry-driven catalog**: `home/index.html.erb` iterates `Calculator.active.order(:category, :name)` through a thin read-only `HomeHelper#catalog_calculators`, rendering a `_calculator_card` partial per row from registry metadata. The net effect, in the agent's words: *"a new calculator's FE = its own result partial + its own helper module, editing nothing shared"* — the keystone's whole point, and regen-safe because it's a convention, not a per-calculator hand-edit. It reported **100% line + branch coverage** (672/672 lines, 158/158 branches) on the single-process run, 570 tests passing, with the known parallel SimpleCov merge-artifact noted and CI confirmed to handle it.

**The content side-effect, surfaced before the gate.** The agent flagged, and the assistant relayed to the operator's eyes, that the registry is now *authoritative for catalog copy*: *"Card headings now read the registry `name` (e.g. **'Percentage Calculator', 'Ohms Law Calculator'**) instead of the old short labels ... Ohm's Law's category now shows **'Other'** (per `INVENTORY.md`), where the old hardcoded card said 'Physics'."* The assistant named the two judgment calls explicitly — the longer "… Calculator" headings and *"'Ohms Law' lost its apostrophe"* — and located the fix: *"Both are fixable in `INVENTORY.md` (PM) if you'd rather the catalog read 'Ohm's Law' / shorter names — the point is the source is now the registry, not hardcoded ERB."* This is the keystone's intended consequence made concrete: catalog copy moved from hardcoded view text to PM-maintained registry data, so changing it is now an INVENTORY/PM edit, not an ERB edit.
