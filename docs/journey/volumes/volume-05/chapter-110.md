## Chapter 110 — "Yikes, can we make this a nicer little UI?": the QA verdict table designed, built, and shipped (2026-06-15)

The harvest closed first. Chapter 109 left the `#143` set (`#176`/`#178`/`#179`) QA-PASS-but-held and `#181` (journey ch.107–109) merge-ready. This chapter opens with all of it landing — and then takes a detour the operator improvised on the spot, which became the iteration's first agent change.

**The harvest finished cleanly.** The orchestrator reconciled the broadened `--wide` wording across all three `#143` layers (the rework, in Chapter 109, had broadened the `--wide` criteria to cover *plain unit-less* large numbers — MMR's 7-digit statistics, Age's Total-hours — after a clipping regression surfaced). With the three layers re-gated and green, the orchestrator declared it: *"🎉 The entire harvest is green."* The operator said *"Merge, then add two loose ends as needed,"* and the four PRs merged sequentially — `#176` (code, `Closes #143`) → `#178` (frontend.md) → `#179` (DESIGN.md) → `#181` (journey) — landing `main` at `e49ce74`. The two "loose ends" (the recurring `bin/ci-watch --pr` NO-RUN flake, now confirmed *broader* than `--pr` since `--sha`/`--run` hit it too, and a new `bin/ci-screenshots` baseline-source quirk where it picks the latest `main` run even when that run lacks the screenshot artifact) were folded into `#169` as a consolidated QA-tooling note rather than filed separately. The orchestrator summarized the post-harvest state: each fix now *"durable across code + agent def + design doc."*

**The detour — a demonstration that turned into a redesign.** With the harvest done and the iteration teed up, the operator asked for something small first: *"Standby - until then, can you pick a recent PR and run the QA agent on it and show me the canned result table as an example?"* The orchestrator ran the QA agent on `#174` (the numeric guard, a changed-calculator PR so all three facets fire) purely as a demonstration. The QA agent returned its current output format — a fenced plain-text block with line-prefix labels (`QA PASS:` / `classification:` / `CI PASS:` / `VISUAL PASS:` / `DB PASS:`). The orchestrator pasted it back verbatim with a how-to-read-it gloss. The operator's reaction was immediate: *"Yikes, can we work on making this a nicer, more polished little UI in terminal? A proper table? Let's actively iterate on the solution and then send an agent to build + PR."*

**Brainstorming the format before building it.** The orchestrator treated this as design work and pulled up the superpowers **brainstorming skill** rather than jumping to an edit — *"This is design work on the QA agent's output — let me pull up the brainstorming skill to iterate properly before we hand it to a build agent."* It explored the current spec (`.claude/agents/quality-assurance-agent.md` §"Output format", lines 192–212) and named two constraints to hold throughout: the format must stay *"scannable by the orchestrator"* (the main thread acts on the verdict) and must handle *"variable-length detail (CI job lists, 40+ shot adjudications, DB shapes) — so a rigid all-cells table can't hold everything."* Because the artifact *is* terminal monospace, it iterated using terminal previews rather than a browser mockup (*"more faithful than a browser mockup here"*).

**Two real design decisions surfaced.** The chosen shape was a **hybrid box summary + detail** — a boxed header + three-row summary table, with variable-length evidence flowing *below* the box (un-boxed). But the orchestrator caught a correctness trap before writing the spec: *"Emoji like ✅/❌ are double-width in most terminals (they occupy 2 character cells), so inside a box-drawing border they push the right edge out of alignment — the polished box ends up ragged."* The decision was to use **single-width glyphs** (`✓ PASS` · `✗ FAIL` · `⚠ BLOCKED` · `○ N/A`) so the boxes always align in a raw code block. The design proposed a header box (title + PR# on the top border, verdict glyph+word pinned right), a `FACET │ RESULT │ SUMMARY` summary table (always all three rows, N/A shown never omitted), and a detail section below the box where the root-cause/per-shot/DB content lives — with both a PASS and a FAIL worked example. The operator approved with a terse *"y."*

**The build, and a "verify it myself" beat.** Since agent-definition edits are outside the build agents' write boundaries (`.claude/agents/` is forbidden to them), the orchestrator dispatched a **general-purpose agent** with the agreed design embedded, on branch `fix/169-qa-verdict-table` (referencing `#169`, not closing it). The agent returned `PR #182` — and flagged that *"the verbatim examples as provided had width drift: the box rows came out at 52/53/54 monospace columns,"* which it normalized to exactly **53 columns** per the task's instruction to fix drift before committing. It also self-reported a familiar wrinkle: *"my first Edit landed in the main checkout rather than the worktree; I copied it into the worktree and reverted the main checkout."* The orchestrator treated both notes as reasons to check directly rather than trust: *"since alignment is the whole point (and a build agent's 'first Edit landed in main checkout' note is a yellow flag), I'll verify the committed file myself rather than trust it."* It confirmed *"all box lines are exactly 53 columns ... junctions aligned, and the main checkout is clean."*

**Shipped — and dogfooded live.** The operator instructed *"Merge when done. Also, let's begin the iteration now please."* The orchestrator gated `#182` (agent-def doc → non-UI lane) and asked the QA agent to optionally render the new box format in its own verdict. It came back **QA PASS** with the box table dogfooded in its own output — so the format's first live appearance was the gate of the PR that introduced it. `#182` merged, `main` at `7f15521` — *"the complete post-harvest agent set (numeric guard + stat-grid component + the new QA verdict table)."* From here, every QA gate emits the polished box table.

**Agent/doc-driven? ✅ — a UI-polish ask routed straight into an agent definition.** What began as *"show me the canned result table as an example"* became a small but clean instance of the experiment's loop: the operator disliked the output, so the *agent's output-format spec was redesigned* (through the brainstorming skill, with a genuine alignment-correctness decision baked in) rather than the format being tweaked ad hoc. The change lives in `.claude/agents/quality-assurance-agent.md`, so every future gate reproduces it. Notable too is the orchestrator's "verify it myself" reflex on an alignment-critical, lane-leak-flagged build — trusting the contract's gate but spot-checking the load-bearing detail by hand.
