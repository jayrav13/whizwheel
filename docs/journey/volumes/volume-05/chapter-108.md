## Chapter 108 — The numeric guard, reviewed three ways: a silent Base-invariant hole caught, the cast-seam rework, and the manual intent-vs-result check (2026-06-14)

This chapter is the #109/#110 fix playing out end-to-end as a *review-driven loop* — the densest demonstration yet of the experiment's core thesis running in anger. The bug is simple (fractional/non-numeric input slips past validation); what makes it worth a chapter is *how* the fix was vetted: the pr-review-toolkit reviews caught two real findings that CI and the visual gate alone would have shipped, the rework moved the mechanism to a better seam, the operator demanded a manual intent-vs-result pass, and every durable convention drove up into the agent definition.

**The first fix landed as PR #174 — and was immediately reviewed three ways.** The backend agent's first cut lifted the fix cleanly into `Calculators::Base`: it overrode `assign_attributes` to capture the raw pre-cast value of every `:decimal`/`:integer` attribute (discovered generically via `attribute_types`, no per-calculator wiring), then validated *that* raw value with a regex before the cast could swallow bad input. *"This propagates to **all** decimal/integer attributes across every calculator ... no per-calculator fix needed."* 579 tests, 100% line+branch. The QA gate ran the UI lane (it touches shared calculator behavior). And — at the operator's *"Yep fire all 3"* — two toolkit agents ran against it.

**`pr-test-analyzer` caught an over-narrowing regression.** Its finding, which the orchestrator relayed verbatim:

> *"**Scientific notation is now silently *rejected*.** The new `NUMERIC` regex rejects `"1e3"`/`"2.5e2"` even though `BigDecimal` accepts them and ActiveModel cast them fine *before* this PR. The fix was meant to reject garbage (`"abc"`), but it also narrowed valid input — and nothing tests this either way."*

The orchestrator's read placed the call where it belonged: *"That's a real, unintended behavior change in a shared `Base` guard affecting every calculator ... rejecting input that `BigDecimal` handles losslessly is over-broad — the guard's job is to catch corruption, and `"1e6" → 1000000` isn't corruption."* But it flagged it as a product decision (do whizwheel inputs accept scientific notation?) for the operator. The operator chose **"Fix it."**

**`silent-failure-hunter` caught more — a silent hole in a Base invariant.** This is the chapter's load-bearing finding. The orchestrator: *"The `silent-failure-hunter` on #174 found **more** than the test gap."* The MEDIUM finding: *"raw capture only happens in `assign_attributes`, so `calc.foo = "abc"` via the per-attribute writer **bypasses the guard entirely** (silent coercion returns) and a stale raw can cause a false 422. Today's web path is safe (controller uses `.new(params)`), but it's a hole in a Base invariant rule #1 depends on."* This is precisely the class of bug that does not surface in CI (the web path was clean) or the visual gate (no pixel moves) — a latent invariant hole in shared machinery, found only by a reviewer reading the *design* of the error-handling path. The orchestrator's verdict on the toolkit's value was immediate and unhedged: *"the writer-bypass hole wouldn't have shown up in CI or the visual gate."*

**The rework collapsed all findings into a better mechanism — the cast seam.** Rather than ship-and-chase, the orchestrator consolidated the three findings (sci-notation over-narrowing, the writer-bypass MEDIUM, an already-`Numeric` LOW) into one cleaner approach: *"**capture at the type-cast seam and validate by attempting the real cast** (not a hand-rolled regex) — that's assignment-path-independent *and* accepts exactly what the cast accepts."* The reworked backend agent delivered exactly that:

- **Raw capture moved to `#_write_attribute`** — *"the single private method every assignment path funnels through (`.new`, `assign_attributes`, `update`, and the per-attribute writer `obj.attr = …`)."* The `assign_attributes` override is *gone*; the guard is now assignment-path-independent, closing the writer-bypass, and a corrective re-assignment overwrites the captured raw so there's no stale false-422.
- **The regex is deleted; validation is parse-based.** Each `:decimal`/`:integer` attribute is backed by a guarded `ActiveModel::Type` subclass (`Calculators::Type::Decimal`/`Integer` sharing `NumericGuard`), installed transparently by overriding `Base.attribute` — *"calculators still declare plain `:decimal`/`:integer` with zero per-calculator change."* Validity is decided by `BigDecimal(raw, exception: false)` being non-nil and *finite* (decimals) plus `.frac.zero?` (integers).
- **Sci-notation is now accepted losslessly** — and a sharp detail surfaced: *"`"2e3"` casts to **2000 for integers** (the stock `:integer` cast yields 2, since `String#to_i` stops at the `e`)."* The fix didn't just restore sci-notation; it made the integer cast *more correct* than stock Rails.

**The operator demanded a manual intent-vs-result review.** After the rework, the operator said: **"Review #174 to verify intent vs result."** The orchestrator pulled the full diff and verified each directive it had sent the rework agent against the actual code, in a six-row table — every directive (parse-based sci-notation, integer lossless, writer-bypass closed at the cast seam, already-`Numeric` accepted, test breadth, 422+no-row+pure-math+100%) marked ✅. It went further with hand-run correctness spot-checks against the code: that `"Infinity"`/`"NaN"` parse to non-finite BigDecimal and are filtered by `.finite?`; that init ordering is safe (`@raw_numeric_inputs = {}` set *before* `super` so writer-capture during assignment doesn't hit a nil hash); that the lossy cast fallback (garbage→0) is *never used* because `compute` is gated on `valid?`; and that dropping the now-unreachable `only_integer` from Amortization was correct (it'd break 100% branch coverage). Its conclusion: *"**Intent and result match — cleanly** ... The design is genuinely good — not a patch ... No blocking issues, no follow-ups needed."* This manual pass is significant: it is the orchestrator reviewing *PR content* (explicitly fair game) while the CI/screenshot tooling stayed with the QA agent — and it is exactly the check the operator later asked to *automate* (Chapter 109's #180).

**The durable half — codified into the agent definition.** True to the Chapter 106 commitment (and because the backend agent cannot write its own definition, the unbuilt meta-agent #72), the orchestrator authored the convention into `.claude/agents/backend.md` itself, as **PR #175**, in its own worktree. When the #174 rework moved the mechanism from `assign_attributes` to the cast seam, the orchestrator *re-aligned #175's wording* to match — *"#175 now matches #174's actual mechanism (cast-seam capture + parse-based, lossless-accepting validation), with the two durable invariants spelled out so a regen reproduces them"* — and re-gated it. This is the coupling made explicit: the code fix and the agent-def codification are kept in lockstep so a regeneration sweep reproduces the *same* fix, not a stale earlier version of it.

**Both gated PASS, both merged.** The QA gate returned PASS on the reworked #174 (CI green, visual lane confirmed the new "is not a number" error states render on-brand and *don't exist on `main`* — proving the fix renders — happy-path unchanged, and the DB facet verified garbage→no-row + sci-notation-accepted against the actual PR head) and PASS on the re-aligned #175. The operator said **"merge 174/175"**; the orchestrator merged #174 (code) then #175 (convention) sequentially, leaving `main` at `873c7d5`: *"The **#109/#110 fix is fully landed** — code (#174) + the regen-proof convention (#175)."*

**Agent/doc-driven? ✅ — and a textbook run of the loop.** Every layer of the experiment's machinery did its job and they composed: the toolkit reviews (advisory) caught a silent Base-invariant hole and an over-narrowing regression that CI and the visual gate could not; the operator made the product call ("fix it") and demanded the manual intent-vs-result verification; the QA gate proved the reworked code green/on-brand/persistence-correct; and the fix landed as a *paired set* — code that propagates through `Base` **and** the convention codified in `backend.md` so rule #1's regen sweep reproduces it rather than erasing it. The one structural gap remains named, not resolved: the durable codification fell to the orchestrator because no registered agent owns agent definitions (#72).
